Publishing from Agentforce Vibes to GitHub

A complete guide for exporting your Vibes-generated code from Salesforce and publishing it to GitHub for version control and collaboration

Overview

When you build with Agentforce Vibes inside Salesforce, your code lives in your org. To version control it, deploy it to other orgs, or share it with your team, you need to export it to GitHub using the Salesforce CLI.

This guide will walk you through the complete process of:

  • Setting up the Salesforce CLI
  • Retrieving your Vibes-generated code
  • Creating a local Salesforce DX project
  • Publishing to GitHub
  • Deploying to other Salesforce orgs

Prerequisites

Before you begin, ensure you have:

  • Salesforce CLI — Install from developer.salesforce.com/tools/salesforcecli
  • GitHub Account — Create at github.com/signup
  • Git — Install from git-scm.com/downloads
  • Salesforce Org Access — Access to your org where you used Agentforce Vibes
TIP: New to Salesforce CLI? See the Salesforce CLI Setup Guide for complete installation and configuration instructions.
1

Authenticate Salesforce CLI

First, authenticate the Salesforce CLI with your org where you used Agentforce Vibes:

Terminal 
sf org login web --alias my-vibes-org

This command will:

  1. Open your default browser
  2. Prompt you to log in to Salesforce
  3. Save the authentication with the alias "my-vibes-org"

Verify Your Connection

Confirm the CLI is connected to your org:

Terminal 
sf org list

You should see your org listed with the alias you created.

TIP: Learn more about org authentication in the Salesforce CLI Authorization Guide.
2

Create a Local Salesforce DX Project

Create a new Salesforce DX project structure on your local machine:

Terminal 
# Create project directory
mkdir pronto-vibes-extension
cd pronto-vibes-extension

# Initialize Salesforce DX project
sf project generate --name pronto-vibes-extension

Project Structure Created

Your new project will have this structure:

File Structure 
pronto-vibes-extension/
├── force-app/
│   └── main/
│       └── default/
│           ├── classes/
│           ├── objects/
│           └── ...
├── sfdx-project.json
├── config/
└── scripts/
TIP: Learn about Salesforce DX project structure in the Salesforce DX Project Configuration Guide.
3

Retrieve Metadata from Your Org

Pull the code you created in Agentforce Vibes from your Salesforce org:

Option 1: Retrieve Specific Components

Terminal 
# Retrieve your Apex classes
sf project retrieve start --metadata ApexClass:OrderStatusAction --target-org my-vibes-org
sf project retrieve start --metadata ApexClass:OrderStatusActionTest --target-org my-vibes-org

# Retrieve custom objects
sf project retrieve start --metadata CustomObject:Order__c --target-org my-vibes-org

Option 2: Use a Manifest File

Create a package.xml file to specify exactly what to retrieve:

package.xml 
<?xml version="1.0" encoding="UTF-8"?>
<Package xmlns="http://soap.sforce.com/2006/04/metadata">
    <types>
        <members>OrderStatusAction</members>
        <members>OrderStatusActionTest</members>
        <name>ApexClass</name>
    </types>
    <types>
        <members>Order__c</members>
        <name>CustomObject</name>
    </types>
    <version>60.0</version>
</Package>

Then retrieve using the manifest:

Terminal 
sf project retrieve start --manifest package.xml --target-org my-vibes-org

Verify Retrieved Files

Terminal 
ls -la force-app/main/default/classes/
ls -la force-app/main/default/objects/
TIP: See the Salesforce CLI Project Commands Reference for all retrieve options.
4

Initialize Git Repository

Set up version control for your retrieved code:

Terminal 
# Initialize git
git init

# Create .gitignore for Salesforce projects
cat > .gitignore << 'EOF'
# Salesforce
.sfdx/
.sf/
.localdevserver/
config/*.org
.vscode/

# Logs
*.log

# OS
.DS_Store
Thumbs.db

# Dependencies
node_modules/
EOF

# Add all files
git add .

# Create initial commit
git commit -m "Initial commit: Vibes-generated OrderStatusAction for Pronto agent"
TIP: New to Git? Check out the Pro Git Book for a comprehensive introduction.
5

Create GitHub Repository

Option A: Via GitHub Web UI

  1. Go to github.com/new
  2. Repository name: pronto-vibes-extension
  3. Description: "Custom Apex actions for Pronto agent built with Agentforce Vibes"
  4. Choose Public or Private
  5. Do NOT initialize with README (you already have files)
  6. Click Create repository

Option B: Via GitHub CLI

If you have the GitHub CLI installed:

Terminal 
gh repo create pronto-vibes-extension --public --source=. --remote=origin --push
TIP: Learn more in the GitHub Repositories Quickstart Guide.
6

Push to GitHub

Link your local repository to GitHub and push your code:

Terminal 
# Add GitHub remote (replace YOUR_USERNAME)
git remote add origin https://github.com/YOUR_USERNAME/pronto-vibes-extension.git

# Push to GitHub
git branch -M main
git push -u origin main

Verify Your Code on GitHub

Visit https://github.com/YOUR_USERNAME/pronto-vibes-extension to see your published code!

Success!

Your Vibes-generated code is now on GitHub, ready for:

  • Version control and collaboration
  • Deployment to other Salesforce orgs
  • Sharing with your team
  • CI/CD pipeline integration

Ongoing Workflow

When You Make Changes in Vibes

  1. Make changes in Agentforce Vibes in Salesforce
  2. Retrieve updates to your local project:
Terminal 
sf project retrieve start --metadata ApexClass:OrderStatusAction --target-org my-vibes-org
  1. Review changes:
Terminal 
git status
git diff
  1. Commit and push:
Terminal 
git add .
git commit -m "Update: Enhanced error handling in OrderStatusAction"
git push

Deploy to Another Org

Terminal 
# Authenticate with target org
sf org login web --alias target-org

# Deploy your code
sf project deploy start --target-org target-org

# Validate before deploying to production
sf project deploy validate --target-org production-org --test-level RunLocalTests
TIP: Learn about deployment strategies in the Salesforce DX Deployment Guide.

Troubleshooting

Issue: "This directory does not contain a valid Salesforce DX project"

Solution:

Terminal 
# Ensure you're in the project directory
cd pronto-vibes-extension

# Verify sfdx-project.json exists
ls sfdx-project.json

Issue: "No Salesforce org is authenticated"

Solution:

Terminal 
# List authenticated orgs
sf org list

# Re-authenticate
sf org login web --alias my-vibes-org

Issue: "Unable to retrieve metadata"

Solution:

Terminal 
# Check metadata API name (case-sensitive)
sf org list metadata --metadata-type ApexClass --target-org my-vibes-org

# Use exact names from output
sf project retrieve start --metadata ApexClass:OrderStatusAction --target-org my-vibes-org

Issue: Push rejected (non-fast-forward)

Solution:

Terminal 
# Pull latest changes first
git pull origin main --rebase

# Then push
git push
