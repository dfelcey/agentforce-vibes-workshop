Extend Pronto with Agentforce Vibes

Learn how to use Agentforce Vibes within Salesforce to build and deploy Apex actions for your Pronto agent using natural language

Workshop Overview

In this workshop, you'll learn how to use Agentforce Vibes — Salesforce's enterprise-grade AI-powered development environment — to extend your Pronto agent with custom Apex actions. You'll work directly within your Salesforce org to build, deploy, and test new agent capabilities using natural language prompts.

What You'll Learn

  • How to launch and configure Agentforce Vibes within your Salesforce org
  • How to use natural language to generate production-ready Apex code
  • How to deploy and test Apex actions for Agentforce agents
  • How to create and configure subagents within your Pronto agent
  • How to integrate custom actions into subagents

What You'll Build

Two complete features for your Pronto agent:

  • Order Status Action — Look up order information and delivery dates
  • Loyalty Subagent — A dedicated subagent with a custom action to retrieve customer loyalty points
⏱️

Duration

~45 minutes

Level

Intermediate

Prerequisites

Before starting this workshop, ensure you have:

  • Salesforce Org Access — A Salesforce org with Agentforce enabled
  • Pronto Agent — A configured Pronto agent (complete the core Agentforce Builder Workshop first)
  • Order Object — The Order__c custom object with fields: Order_Number__c, Status__c, and Estimated_Delivery_Date__c (used in Steps 3-4)
  • System Permissions — Ability to create and deploy Apex classes, create subagents, and modify Agentforce agents
Note: The Order__c object is only needed for the Order Status action (Steps 3-4). The Loyalty subagent (Steps 5-7) doesn't require any custom objects — it uses a simulated points lookup for workshop simplicity.
1

Launch Agentforce Vibes

What is Agentforce Vibes?

Agentforce Vibes is Salesforce's enterprise-grade AI-powered development environment. Unlike basic code assistants that generate snippets, Vibes understands your org's metadata, follows established patterns, and works as an autonomous coding partner that can plan, build, test, and deploy through natural language interaction.

Access Vibes in Your Salesforce Org

  1. Log in to your Salesforce org at login.salesforce.com
  2. From Setup, enter Agentforce Vibes in the Quick Find box
  3. Click Agentforce Vibes to open the IDE interface
  1. Accept the terms and conditions if this is your first time launching Vibes
  2. Wait for Vibes to initialize — it will automatically create a Salesforce DX project connected to your org
TIP: On first launch, Vibes will analyze your org's metadata and create a project structure. This may take a few moments. You'll see a VS Code-compatible editor with an Explorer panel, Org Browser, terminal, and the Agentforce chat interface.

Verify Your Environment

Once Vibes loads, you'll see a VS Code-compatible interface. Take a moment to familiarize yourself with the key areas:

  • Activity Bar (left) — Contains icons for Explorer, Search, Source Control, and Extensions
  • Org Browser — Shows your connected org and metadata (cloud icon in Activity Bar)
  • Agentforce Chat — The AI assistant panel on the right side
  • Terminal — Accessible at the bottom for running CLI commands
  • Status Bar — Shows your org connection status at the bottom

Verify your environment is ready:

  • ✓ The Org Browser shows your connected org name
  • ✓ The Agentforce chat panel is visible on the right
  • ✓ The terminal is accessible at the bottom
  • ✓ You can see your org's metadata in the Explorer
2

Configure Your Salesforce Project

Before building with Vibes, you need to enable key features in your Salesforce org and configure your development environment. This ensures Vibes can communicate with your org and access the right metadata.

Enable MCP Service (Beta)

MCP (Model Context Protocol) allows Vibes to connect to your Salesforce org using a standardized AI protocol.

  1. In your Salesforce org, navigate to Setup
  2. In the Quick Find box, search for "User Interface"
  3. Click User Interface in the results
  4. Scroll down and check the box for "Enable MCP Service (Beta)"
  5. Click Save
What is MCP? Model Context Protocol (MCP) is an open standard that allows AI tools like Vibes to securely communicate with your Salesforce org, read metadata, and execute commands. Enabling this service allows Vibes to understand your org's structure.

Activate Salesforce MCP Servers

MCP Servers provide specific capabilities to Vibes, like reading objects or accessing Salesforce APIs.

  1. In Setup, search for "MCP Servers" in Quick Find
  2. Click MCP Servers
  3. Under the Salesforce Servers tab, you'll see available servers
  4. Activate these two servers by clicking the toggle or checkbox:
    • sobject-all — Provides access to all standard and custom objects
    • salesforce-api-context — Provides Salesforce API context and metadata
  5. Verify both servers show as "Active" or "Enabled"
TIP: Both servers are required for complete functionality. The sobject-all server lets Vibes understand your custom objects like Order__c, while salesforce-api-context provides general Salesforce metadata access.

Configure MCP Servers in Vibes

Now that MCP is enabled in your org, configure it within the Agentforce Vibes interface.

  1. In the Agentforce Vibes window, look for the Agentforce Vibes Sidebar (usually on the left)
  2. Click Manage MCP Servers or find the MCP Server management section
  3. You should see a list of available MCP servers
  4. Toggle on or activate all three servers:
    • sobject-all
    • salesforce-api-context
    • Any additional Salesforce-related servers shown
  5. Click the configuration icon (gear or settings) next to each server to verify available tools
TIP: When you configure a server, you'll see the tools it provides (like Salesforce DX commands). This shows what Vibes can do with that connection.

Open the Agentforce Chat Panel

With MCP configured, you're ready to start interacting with Vibes. Let's open the AI chat interface where you'll give instructions.

Locating the Agentforce Chat Interface

The Agentforce chat is your AI assistant within Vibes. Here's how to find it:

Find the Agentforce Vibes Icon

Look for this icon in the Activity Bar on the left side of your Vibes window:

Click this icon to open the Agentforce chat panel

The Vibes icon is located at the top of the Activity Bar (left sidebar). Clicking it opens the chat panel where you'll type your prompts.

How to use the chat:
  1. Click the Vibes icon shown above to open the chat panel
  2. Type your prompts in the input box at the bottom that says "Type a message..."
  3. Send your prompt by pressing Enter or clicking the send arrow (→)

Give Vibes a Complete Plan

Instead of giving Vibes individual prompts for each step, you can provide a comprehensive plan that covers the entire workshop. This lets Vibes understand the full context and execute all steps efficiently.

In the Agentforce chat input box at the bottom of the chat panel, copy and paste this complete plan:

Complete Workshop Plan 
I need to extend my Pronto agent with custom Apex actions and a new Loyalty subagent. Please create a plan for:

1. Pull metadata from my org:
   - Order__c custom object (with Order_Number__c, Status__c, Estimated_Delivery_Date__c fields)
   - Pronto_Service_Agent configuration

2. Create OrderStatusAction Apex class:
   - Invocable from Agentforce (@InvocableMethod)
   - Input: order number (String)
   - Query Order__c using Order_Number__c field
   - Return: order status (Status__c) and estimated delivery date (Estimated_Delivery_Date__c) as Strings
   - Include error handling for orders not found
   - Create test class with 100% coverage
   - Label the invocable method as "Get Order Status"

3. Deploy OrderStatusAction to my org with test execution

4. Create LoyaltyPointsAction Apex class:
   - Invocable from Agentforce (@InvocableMethod)
   - Input: customer email (String)
   - Return: random number of loyalty points between 100 and 10000 (Integer)
   - Label the invocable method as "Get Loyalty Points"
   - Create test class with 100% coverage

5. Deploy LoyaltyPointsAction to my org with test execution

After successful deployment, I'll manually:
- Add "Get Order Status" action to the main Pronto agent
- Create a Loyalty subagent in Agent Builder with these instructions:
  "You help customers with loyalty program questions. When a customer asks about their points or rewards, use the Get Loyalty Points action with their email address. Our loyalty program: 1 point per dollar spent, 100 points = $1 off. Be friendly about rewards. For order status or delivery questions, refer them to our main support."
- Add "Get Loyalty Points" action to the Loyalty subagent
- Test routing between main agent and Loyalty subagent

Please create a plan first, then I'll review it before you proceed.
Why Use a Complete Plan?
  • Better Context: Vibes understands the full scope and can make better architectural decisions
  • Fewer Prompts: One comprehensive prompt instead of multiple back-and-forth exchanges
  • Consistent Code: Vibes sees both Apex classes together and can ensure consistency
  • You Stay in Control: Vibes creates a plan first, you review and approve before execution

Use the Plan Feature

Now that you've pasted the complete plan, use Vibes' Plan feature to organize the work:

  1. Click the "Plan" button in the chat interface (or press the keyboard shortcut if available)
  2. Wait for Vibes to analyze your plan — Vibes will break down the steps, identify dependencies, and create a structured execution plan
  3. Review the plan that Vibes creates:
    • Check that Vibes understood all requirements
    • Verify the order of operations makes sense
    • Confirm the Apex class specifications match your needs
  4. Click the "Act" button to execute the plan — Vibes will now:
    • Pull metadata from your org (Order__c and Pronto_Service_Agent)
    • Generate the OrderStatusAction Apex class and test
    • Deploy OrderStatusAction to your org
    • Generate the LoyaltyPointsAction Apex class and test
    • Deploy LoyaltyPointsAction to your org
Why use Plan → Act? The Plan feature lets you review Vibes' approach before execution. This gives you a chance to catch misunderstandings, adjust requirements, or verify the architecture before any code is deployed to your org.
Plan Execution Complete! Vibes has now:
  • ✓ Retrieved metadata from your org
  • ✓ Generated OrderStatusAction and LoyaltyPointsAction with test coverage
  • ✓ Deployed both Apex classes to your Salesforce org
  • ✓ Verified successful deployment and test execution

You're now ready to configure the actions in Agent Builder!

3

Add Order Status Action to Pronto

Configure the Action in Agent Builder

Now that the OrderStatusAction Apex class is deployed, add it to your Pronto agent.

  1. Navigate to Setup in your Salesforce org
  2. Search for Agentforce Agents in Quick Find
  3. Click on your Pronto Agent to open it
  4. Click the Actions tab
  5. Click New Action
  6. Select Apex as the action type
  7. Search for and select OrderStatusAction
  8. Verify the action configuration:
    • Action Label: Get Order Status
    • Input: Order Number (String)
    • Outputs: Order Status (String), Estimated Delivery Date (String)
  9. Click Finish or Save
TIP: The action label "Get Order Status" is what the agent will see when deciding which action to use. The @InvocableMethod label in your Apex class determines this display name.
4

Create a Loyalty Subagent

What are Subagents?

Subagents are specialized agents within your main Pronto agent that handle specific domains or tasks. They have their own instructions, actions, and knowledge, allowing you to organize complex agent behaviors into focused, manageable components.

TIP: In the Agentforce Builder Workshop, you may have already created other subagents. Subagents help organize your agent's capabilities by topic area (e.g., Orders, Loyalty, Support).

Create the Loyalty Subagent

  1. Navigate to Setup in your Salesforce org
  2. Search for Agentforce Agents in Quick Find
  3. Open your Pronto Agent
  4. In the agent canvas, look for the Subagents or Topics section
  5. Click New Subagent or Add Topic
  6. Configure the subagent:
    • Name: Loyalty
    • API Name: Loyalty
    • Description: Specializes in customer loyalty program inquiries, including points balance lookups, rewards information, and program benefits. Routes queries about loyalty points, rewards redemption, and membership tiers.
  7. Click Finish or Save to create the subagent
TIP: The description helps the main Pronto agent understand when to route queries to this subagent. Include keywords that customers might use (loyalty, points, rewards, membership).

Add Subagent Instructions

Instructions define how the Loyalty subagent should behave and when to use its actions. Clear instructions ensure accurate routing and helpful responses.

Subagent Instructions 
You help customers with loyalty program questions.

When a customer asks about their loyalty points balance, use the Get Loyalty Points action. Ask for their email address if they haven't provided it.

Program details:
- Customers earn 1 point per dollar spent
- 100 points = $1 off future orders

Be friendly and enthusiastic about helping customers with their rewards. If they ask about order status or delivery, let them know that's handled by a different part of the system.
  1. Open your newly created Loyalty subagent
  2. Find the Instructions field
  3. Paste the instructions above into the field
  4. Click Save
Important: Well-written instructions are crucial for subagent routing. The main Pronto agent uses the description and instructions to decide when to activate this subagent. Clear guidelines about when to use actions (like "Get Loyalty Points") ensure the subagent behaves correctly.
5

Add Loyalty Points Action

Add Action to Loyalty Subagent

Now wire the action into your Loyalty subagent:

  1. Return to Agent Builder in your Salesforce org
  2. Open your Pronto Agent
  3. Navigate to the Loyalty subagent you just created
  4. In the subagent view, click the Actions tab
  5. Click New Action
  6. Select Apex as the action type
  7. Search for and select LoyaltyPointsAction
  8. Verify the action label is Get Loyalty Points
  9. Review the Input/Output fields:
    • Input: Customer Email (String)
    • Output: Points (Integer)
  10. Click Save
TIP: Because this action is added to the Loyalty subagent (not the main Pronto agent), it will only be available when the Loyalty subagent is activated.
6

Test the Loyalty Subagent

Preview in Agent Builder

Test your new Loyalty subagent and its action using Agent Builder's preview feature.

  1. In Agent Builder, ensure you're viewing your Pronto Agent
  2. Click the Preview button in the top right
  3. Wait for the preview chat interface to load
  4. In the chat input, type a test query:
Test Query 
How many loyalty points do I have? My email is customer@example.com

Verify the Response

Check that your Loyalty subagent is working correctly:

  1. The Pronto agent should route your query to the Loyalty subagent
  2. You should see an indication that the Get Loyalty Points action was called
  3. Click Interaction Details or View Trace to see the full execution flow
  4. Verify the response includes:
    • Recognition that this is a loyalty points query
    • A number between 100 and 10,000 (your loyalty points)
    • A friendly message from the Loyalty subagent
  5. In the trace, confirm the query was routed to the Loyalty subagent (not the main agent)
TIP: Try different test scenarios:
  • "What are my loyalty points?" (without providing email - should ask for it)
  • "Check my rewards balance for john@example.com"
  • "How does the loyalty program work?" (should get general info, not call the action)

Test Multiple Capabilities

Verify that your Pronto agent can handle different types of queries:

Additional Test Queries 
1. What's the status of order ORD-12345?
2. How many loyalty points does sarah@example.com have?
3. When will my order arrive?

The agent should correctly route:

  • Order queries → Main agent (using OrderStatusAction from earlier steps)
  • Loyalty queries → Loyalty subagent (using LoyaltyPointsAction)

Troubleshooting

If the Loyalty subagent doesn't work as expected:

  • Action not called: Check the Loyalty subagent instructions and ensure they clearly describe when to use the Get Loyalty Points action
  • Not routing to subagent: Review the subagent instructions and make sure keywords like "loyalty" and "points" are mentioned
  • Error response: Review the Interaction Details for error messages. Check that LoyaltyPointsAction deployed successfully
  • Wrong subagent activated: Refine the subagent instructions to be more specific about when it should activate
