Extend Pronto with Agentforce Vibes

Learn how to use Agentforce Vibes within Salesforce to build and deploy Apex actions for your Pronto agent using natural language

Workshop Overview

In this workshop, you'll learn how to use Agentforce Vibes — Salesforce's enterprise-grade AI-powered development environment — to extend your Pronto agent with custom Apex actions. You'll work directly within your Salesforce org to build, deploy, and test new agent capabilities using natural language prompts.

What You'll Learn

  • How to launch and configure Agentforce Vibes within your Salesforce org
  • How to use natural language to generate production-ready Apex code
  • How to deploy and test Apex actions for Agentforce agents
  • How to integrate custom actions into Pronto subagents

What You'll Build

A complete Get Order Status Apex action that allows the Pronto Customer Service subagent to look up order information and delivery dates for customers.

⏱️

Duration

~30 minutes

📚

Level

Intermediate

Prerequisites

Before starting this workshop, ensure you have:

  • Salesforce Org Access — A Salesforce org with Agentforce enabled
  • Pronto Agent — A configured Pronto agent with the Customer Service subagent (complete the core Agentforce Builder Workshop first)
  • Order Object — The Order__c custom object with fields: Order_Number__c, Status__c, and Estimated_Delivery_Date__c
  • System Permissions — Ability to create and deploy Apex classes and modify Agentforce agents
ℹ️
New to Agentforce Vibes? This workshop introduces you to Vibes as you build. No prior experience with Vibes is required, but familiarity with Salesforce DX and Apex development concepts is helpful.
1

Launch Agentforce Vibes

What is Agentforce Vibes?

Agentforce Vibes is Salesforce's enterprise-grade AI-powered development environment. Unlike basic code assistants that generate snippets, Vibes understands your org's metadata, follows established patterns, and works as an autonomous coding partner that can plan, build, test, and deploy through natural language interaction.

Access Vibes in Your Salesforce Org

  1. Log in to your Salesforce org at login.salesforce.com
  2. From Setup, enter Agentforce Vibes in the Quick Find box
  3. Click Agentforce Vibes to open the IDE interface
  1. Accept the terms and conditions if this is your first time launching Vibes
  2. Wait for Vibes to initialize — it will automatically create a Salesforce DX project connected to your org
TIP: On first launch, Vibes will analyze your org's metadata and create a project structure. This may take a few moments. You'll see a VS Code-compatible editor with an Explorer panel, Org Browser, terminal, and the Agentforce chat interface.

Verify Your Environment

Once Vibes loads, you'll see a VS Code-compatible interface. Take a moment to familiarize yourself with the key areas:

  • Activity Bar (left) — Contains icons for Explorer, Search, Source Control, and Extensions
  • Org Browser — Shows your connected org and metadata (cloud icon in Activity Bar)
  • Agentforce Chat — The AI assistant panel on the right side
  • Terminal — Accessible at the bottom for running CLI commands
  • Status Bar — Shows your org connection status at the bottom

Verify your environment is ready:

  • ✓ The Org Browser shows your connected org name
  • ✓ The Agentforce chat panel is visible on the right
  • ✓ The terminal is accessible at the bottom
  • ✓ You can see your org's metadata in the Explorer
2

Configure Your Salesforce Project

Pull Project Metadata

Before building, Vibes needs context about your org's metadata. Let's retrieve the relevant objects and configurations for your Pronto agent.

In the Agentforce Vibes chat, type:

Prompt 
Pull metadata for Order__c object, Pronto agent configuration, and Customer Service subagent

Vibes will retrieve:

  • The Order__c custom object definition and fields
  • Your Pronto agent and subagent configurations
  • Related permission sets and profiles
  • Existing Apex classes and Lightning Web Components
TIP: By pulling metadata first, Vibes understands your org's schema, naming conventions, and existing patterns. This ensures generated code follows your org's standards and integrates seamlessly.

Verify Metadata Retrieval

After the pull completes, check your Explorer panel:

  • Expand force-app/main/default/objects/Order__c
  • Verify you see the object definition and field files
  • Check that agent configurations appear under aiApplicationConfigs

You're now ready to start building!

3

Generate the Apex Action

Use Natural Language to Build

Now comes the powerful part — you'll use natural language to generate a production-ready Apex action. Vibes will understand your requirements and create complete, tested code.

In the Agentforce Vibes chat, enter this prompt:

Prompt 
Create an Apex class called OrderStatusAction that is invocable from Agentforce. It should accept an order number as a string input, query the Order__c object for a matching record, and return the order status and estimated delivery date as output strings. Include proper error handling and a test class with 100% coverage.

Review the Generated Code

Vibes will generate several files. Review them to understand what was created:

  1. OrderStatusAction.cls — The main Apex class with @InvocableMethod annotation
  2. OrderStatusActionTest.cls — Complete test class with assertions
  3. Vibes automatically follows Salesforce best practices and your org's coding patterns
TIP: Check that the SOQL query includes Order_Number__c, Status__c, and Estimated_Delivery_Date__c fields. The method should be properly annotated with a descriptive label for Agent Builder.

Request Modifications (Optional)

If you need changes, simply ask Vibes in natural language:

Example refinement prompts 
Add a return value for customer email
Handle the case when no order is found
Update the method description to be more specific
4

Deploy to Your Org

Deploy with Vibes

Once you're satisfied with the generated code, deploy it directly from Vibes to your org.

In the Agentforce chat, tell Vibes to deploy:

Prompt 
Deploy the OrderStatusAction class and test class to my org

Vibes will:

  1. Run the Salesforce CLI command sf project deploy start
  2. Execute the test class to verify coverage
  3. Report deployment status and any errors
  4. Show you the deployment results in the terminal

Verify Deployment

Check that your deployment succeeded:

  • Look for "Deploy Succeeded" message in the terminal
  • Verify test coverage is 100%
  • Note the component IDs for the deployed classes
Deployment Errors? If you encounter errors, paste them back into the Vibes chat. Vibes will analyze the error, explain what went wrong, and automatically fix the code before redeploying.
5

Configure the Agent Action

Add Action in Agentforce Builder

Now that your Apex class is deployed, you'll wire it into your Pronto agent using Agent Builder.

  1. In a new browser tab, navigate to Setup in your Salesforce org
  2. Search for Agentforce Agents in Quick Find
  3. Open your Pronto Customer Service Agent
  4. In the agent canvas, click New Action
  5. Select Apex as the action type
  6. Search for and select OrderStatusAction
  7. Set the action Label to Get Order Status
  8. Review the auto-populated Input/Output fields:
    • Input: Order Number (String)
    • Outputs: Status (String), Estimated Delivery Date (String)
  9. Click Save

Add Action to Customer Service Subagent

  1. In Agent Builder, navigate to the Customer Service subagent
  2. Click the Actions tab
  3. Click Add Action and select Get Order Status
  4. In the Instructions field, add guidance for when to use this action:
Subagent Instructions 
When a customer asks about their order status or delivery date, use the Get Order Status action with the order number they provide. If they don't provide an order number, ask for it first.
  1. Click Save
6

Test Your Action

Preview in Agent Builder

Test your new action using Agent Builder's preview feature.

  1. In Agent Builder, click the Preview button in the top right
  2. Wait for the preview chat interface to load
  3. In the chat input, type a test query:
Test Query 
What's the status of order ORD-12345?

Verify the Response

Check that your action worked correctly:

  1. The agent should route your query to the Customer Service subagent
  2. You should see an indication that the Get Order Status action was called
  3. Click Interaction Details to see the full execution trace
  4. Verify the response includes:
    • Order number (ORD-12345)
    • Current status (e.g., "Shipped", "Processing")
    • Estimated delivery date
TIP: Try different scenarios to ensure your action handles edge cases:
  • Query with a non-existent order number
  • Ask about order status without providing a number
  • Try variations like "check my order" or "delivery status"

Troubleshooting

If the action doesn't work as expected:

  • Action not called: Check the subagent instructions and ensure they clearly describe when to use the action
  • Error response: Review the Interaction Details for error messages and verify the Order__c object has test data
  • Missing data: Ensure your test order record has all required fields populated
